# 一、AI 篇：备赛期间如何学习

## 1.1 如何在训练期间完善你的题目

**核心原则**：不要指望比赛 3 天从头开始。备赛期间就要用自己的训练数据把 Skill 的能力"喂"出来。

### 三轮训练法

```
第 1 轮：不看 Skill，自己先做一遍
  → 卡在哪、哪里想不清楚，全部记下来
  → 这些"卡点"就是你后续用 Skill 帮你补的地方

第 2 轮：用 mathskills 重做同一道题
  → 把题目放进 题目/，数据放进 数据/，说"开始求解"
  → Skill 会自动读题审题 → 展示数据总览 → 逐问写 TXT 建模报告
  → 对比 Skill 的建模思路和你自己的思路，找到差距
  → 把你没想到的好方法、好模型记下来（查阅 references/algorithm-library/ 理解原理）

第 3 轮：换一道同类型题，不看 Skill 的建模报告
  → 自己先想方案 → 再用 Skill 做一遍来验证
  → 检验：上一轮学到的方法，这次能自己想到了吗？
  → 如果想到的方案和 Skill 给出的高度吻合 → 这个方法是你的了
```

### 每一轮用 Skill 时要产出的

| 产出 | 说明 |
|------|------|
| 你自己的 `.py` 文件 | 不是复制 Skill 生成的代码，是理解后自己写一版。变量名换自己的风格，注释只留关键决策点 |
| 建模思路笔记 | **手写**，不用 AI 总结。把 Skill 报告里你认可的方法写下来，加上你自己的理解 |
| 踩坑记录 | 这道题哪个模型跑不动、哪个参数调了半天、为什么换了方案 |

### 建立自己的模板库（用 Skill 辅助生成，你自己改写）

| 模板 | Skill 怎么帮你 | 你需要做什么 |
|------|------|------|
| Python 公用头部 | CLAUDE.md 第 190-247 行有完整模板（NATURE_PALETTE + 中文字体 + save_fig） | 复制后修改变量名、配色偏好 |
| 常见模型代码 5-8 份 | references/algorithm-library/ 有 7 类算法详解；references/champions-corner/algorithm-advanced.md 有混合算法方案 | **自己手写**——GA、SA、AHP、TOPSIS、熵权法、GM(1,1)、蒙特卡洛。代码不长，自己写一遍就记住 |
| 常见图表代码 5-8 份 | references/modelviz/template_catalog.yaml 收录了 89 个模板，12 个类别 | 每种图表类型选一个模板，看懂后用自己的风格重写 |
| 论文段落模板 3-5 份 | 论文/sections/ 有 12 个 .tex 模板 | 摘要五段式、模型假设通用表述、灵敏度分析标准写法 |
| LaTeX 主文件 | 论文/论文.tex 宏包齐全 | 直接复用 |

## 1.2 如何让 AI 教你快速学会模型（建模手篇）——以遗传算法为例

### 第一步：先问这个模型的作用是什么

让 Skill 帮你解答："打开 references/algorithm-library/01-优化算法说明.md，找到遗传算法部分。"

理解后用自己的话重写：遗传算法模拟生物进化来找最优解——把可能的解编码成染色体、让好的解繁殖差的淘汰、通过交叉和变异产生新解、一代一代逼近最优。

| 模型 | 自己写还是让 AI 写 | 为什么 |
|------|:--:|------|
| GA、SA、AHP、TOPSIS、熵权法、GM(1,1)、蒙特卡洛 | **自己写** | 代码不长，自己写一遍就记住。AI 生成的查重率高 |
| ARIMA、XGBoost/LightGBM | 可以让 AI 写 | 调库代码，API 统一，AI 痕迹不明显 |

## 1.3 代码手如何去除 AI 痕迹

AI 生成的代码有三个特征：变量名规整（`chromosome`、`fitness_value`）、注释饱和（每一行都有注释）、结构流式（从上到下跑一遍）。

### 五条铁律

**1. 常见模型自己写，变量名用汉语拼音**
- 原因：附录没人认真看，拼音和 AI 的常用变量名不同，降低雷同率
- 注意：这只是为了风格差异，不是碰瓷查重

**2. 代码写成函数型**
- AI 喜欢流式代码；你组织成 `def calc_fitness()`、`def do_crossover()` 等函数
- 函数型天然有"人写的"味道

**3. 不要让 AI 饱和备注**
- AI 连 `x = x + 1` 都写注释；你只在关键决策点备注：为什么选这个方法、参数为什么是这个值

**4. 注释写点你自己的痕迹**
- `# 这里试了三种方法，L-BFGS-B 最快`、`# 为什么不用 GA？30 维跑太慢`
- 这种决策过程 + 主观判断，AI 写不出来

**5. 附录代码在正文中有对应**
- 每段代码第一行：`# 对应论文 5.1.2 节公式(5.3)`
- 评委抽查代码能直接定位 → 加分


# 二、竞赛篇：如何在比赛期间借助 AI 拿大奖

## 2.1 建模手怎么快速选定模型

Skill 自动完成以下工作，你只需要审阅和决策：

**Skill 自动做的事**（CLAUDE.md G2 + G3）：

1. **G2 六维选题评估**：数学类型(15%) + 数据可得性(20%) + 算法复杂度(15%) + 评价清晰度(20%) + 写作难度(15%) + 团队匹配度(15%)。加权总分供你参考。
2. **模型选择决策树**（CLAUDE.md 第 738-770 行）：预测→ARIMA/XGBoost/GM(1,1)/LSTM；评价→AHP/TOPSIS/熵权/DEA；优化→LP/GA/SA/NSGA-II；分类→RF/SVM/K-means
3. **高分组合推荐**：AHP+TOPSIS、XGBoost+Bootstrap、AHP+熵权+TOPSIS、Logistic+蒙特卡洛

**Skill 写 TXT 建模报告时**，会给出 2-3 个候选方法，每个附 ≤30 行 PoC + 真实数据跑出的可行性数值。你的任务不是拍脑袋选，而是看三个维度：

| 维度 | 权重 | Skill 帮你做什么 | 你判断什么 |
|------|:--:|------|------|
| 方法匹配度 | 45% | 自动数据审计（G1 data_audit.md），检测数据分布和异常值 | 模型的前提假设数据满足吗？输出题目需要吗？ |
| 结果可信度 | 35% | PoC 数值 + Baseline 对比 | 数值在合理范围吗？比基线提升多少？ |
| 创新空间 | 20% | algorithm-advanced.md 提供了 4 种创新路径 | 能不能组合/改进/融合？ |

### 评判数据匹配度——Skill 帮你做

**Skill G1 自动输出**：`求解/data_audit.md`（缺失率、异常值 IQR/Z-score、数据类型冲突、清洗建议）

**你自己必须判断的**：
- 先看数据分布——直方图 + 箱线图 + 散点矩阵
- 3σ 处理的前提是数据符合正态分布（CLAUDE.md 防错守则：不符合 → 用 IQR）
- 30 个维度直接做 AHP？→ 荒诞。先 PCA 降维到 5-8 维再 AHP（CLAUDE.md G3 建模类型划分里有评价类步骤）
- 样本量 < 100 → 不要深度学习，走传统 ML（CLAUDE.md 决策树里有明确指引）

**一定要查文献**：Skill G2 会自动 WebSearch 搜索真实论文。行业现有方法 + 革新思路 = 你的创新点。

## 2.2 方法的完整性：本质是论证模型可行

你的模型不是跑通就完了。Skill 通过以下门控确保完整性：

| 环节 | Skill 自动做什么（对应 CLAUDE.md 位置） |
|------|------|
| 数据预处理 | 输出审计报告（G1）。预处理方式必须对应模型要求——为什么用 Min-Max 而不是 Z-score？因为有界约束需要 [0,1] 范围 |
| 模型假设 | 论文规范 3.模型假设："为简化问题，本文做出以下假设"，每条必须附 Justification |
| 模型四问 | 强制规则（G4）：①这是什么模型？②变量是什么（符号/含义/单位）？③公式怎么来的（推导或文献）？④假设是什么？ |
| 误差分析 | 优先 5 折交叉验证（CLAUDE.md 论文规范 6.模型检验） |
| 灵敏度分析 | ≥3 参数联合扰动（CLAUDE.md 论文规范 9.模型灵敏度分析：每问配图+≥3 行解释）。国一标配：LHS/Sobol，不是 OAT |
| 模型数据流 | 数据 → 预处理 → 模型 → 输出 → frozen_numbers.json → 论文。变更传播规则（CLAUDE.md 第 935 行）确保改代码后论文数字不漂移 |

## 2.3 模型的创新性：国一和国二的核心差距

**组合创新**：不是堆砌模型。CLAUDE.md 高分组合表给出了 6 个经典组合。正确示范是将两个模型的优点两两结合：DE+GA、AHP+熵权法、微分方程+蒙特卡洛、回归+SHAP。

**改进创新**：algorithm-advanced.md 给出了每种算法的改进方向表（GA→自适应交叉+小生境，SA→自适应降温速率，PSO→多群协同+扰动重置）。结合文献修正模型，再针对题目增加约束、修改边界——本质上就是更切题。

**融合创新**：跨学科（遗传算法来自生物学、模拟退火来自物理学）+ 机理模型+数据模型（如 PINN——可解释+高精度）。CLAUDE.md 决策树和 algorithm-advanced.md 都覆盖了这些方向。

**讲故事**（CLAUDE.md 论文规范明确要求的叙事结构）：这个问题难在哪 → 现有方法为什么不行 → 我们怎么解决的 → 为什么这样解决合理。评委 30 秒看摘要，抓住他的是叙事，不是模型名。

## 2.4 代码手如何去除 AI 痕迹（比赛实操）

**Skill 生成代码后你做的事**：
1. 用 AI 生成第一版 → 你重构：删饱和注释、加决策注释、改变量名为拼音
2. 加上 CLAUDE.md 的代码头部格式（问题编号 + 模型 + 方法 + 输入输出）
3. 关键步骤写 `# 对应论文 X.X 节`
4. 代码行间加逻辑分段空行
5. try-except 只保留必要的

**快速验证建模手的方案**（Skill G3 PoC 机制）：建模手说用 XX 模型 → 用 ≤30 行代码跑 PoC → 跑不出来趁早换。这是 CLAUDE.md 的硬要求——没有 PoC = 未验证，不能进入 G4。


# 三、分工篇：用 Skill 的协作方式

Skill 本身是按"逐问确认"流程设计的，恰好对应了实战分工：

**建模主导者**：Skill 逐问写 TXT 建模报告时，你在每个报告上做最终决策。另外两位同学也要各自提候选方案——你不是一个人拍板，你是组合+确认者。利用 CLAUDE.md 的模型四问确保完整性，利用 G6 的 32 条反模式自查确保论文质量。

**结果主导者**：Skill 写代码前必须通过 PoC 验证（≤30 行 + 真实数据数值）。你的核心职责是快速判断"方案能不能跑"。结果冻结到 `frozen_numbers.json` 后论文数值全从这里取，防止最后一天改 bug 导致论文数字漂移。

**论文主导者**：可视化在 G4 写论文阶段统一完成。利用 references/modelviz/template_catalog.yaml 的 89 个模板选图，利用 CLAUDE.md 的 Figure Contract（结论→证据链→原型→规格→风险预检）确保每张图都在论证一个具体观点。论文要有叙事线——不是罗列模型名，是讲清楚"为什么这样做"。

### 三人协作 + Skill 时间线

```
Day 1 上午：三人一起读题 → Skill 自动输出题目总览+数据审计+任务栏
Day 1 下午：三人各提候选 → Skill 跑 PoC → 建模主导者组合确认
Day 1 晚上：最终方案确定（PoC 全部通过），数值开始冻结

Day 2 上午：Skill 逐问生成建模报告 → 你审阅 → 代码求解
Day 2 下午：所有结果跑出来（frozen_numbers.json 锁定）
Day 2 晚上：论文初稿完成（可留数值空位），论文主导者开始可视化

Day 3 上午：填完所有数值，图表生成完毕
Day 3 下午：反复改摘要 + 逐条对照 CLAUDE.md G6 的 32 条反模式
Day 3 晚上：G5 编译 → G6 三审计师 → G7 排版优化 → 提交
```

**关键**：Day 2 下午之后不要再改代码。改了就要走"解冻→修改→重冻结"流程（CLAUDE.md 变更传播规则），不然论文数字会漂移。
