# Research Presentation

The presentation is a second evidence artifact, not a decorative summary.

## Workflow

1. Inventory audience, time, language, slide budget, source paper, frozen results, figures, and
   required assets.
2. Build an evidence ledger: every claim, number, equation, figure, table, and limitation gets a
   source pointer.
3. Write a ghost deck with one narrative job and one takeaway per slide before styling.
4. Prefer editable text, equations, tables, and charts. Use source figures only with provenance;
   label any conceptual redraw.
5. Add visible source anchors and speaker-note sources to content slides.
6. Render every slide and check overflow, clipping, readability, aspect ratio, citation anchors,
   and visual monotony.

## Math-modeling defaults

```text
problem -> insight -> assumptions -> model -> algorithm -> validation
-> key results -> sensitivity -> limitations -> direct answers
```

Use the competition paper's frozen values. Do not invent a logo, chart, result, or “improved” claim
to fill a slide. If a PPTX backend is unavailable, provide the outline, source map, and QA status
instead of calling a screenshot-only deck editable.
